## Decisions (do not re-litigate)

1. **The one-time purchase only removes ads.** Every feature stays free.
2. **One release** — everything ships together as 2.0.0.
3. **Utility scope = widgets + adaptive reminders.** Drink types and Apple
   Health are out of 2.0.
4. **Languages = Color Catch's 13**: de, es, fr, it, ja, ko, nl, pl, pt, tr,
   zh (Traditional) in the UI; listings also get en-GB and es-ES.
5. Already in all 175 storefronts — no availability work.

State at decision time: 1.1.0 live, 37 new downloads in 60 days (BR, IN, FR,
GH top), 0 ratings. Ad revenue at this volume is cents per day; ads are a bet
on volume, not current income.

## Workstreams

### A. Widgets — tap to log (~2–3 days)
- `expo-widgets ~56.0.26` + `@expo/ui ~56.0.25` (both SDK 56 bundled). Read
  the v56 docs first (AGENTS.md).
- Small home-screen widget: progress ring + "+250 ml" button. Lock-screen
  (accessory) widget: progress only.
- Widget runtime: no hooks, no async, nothing outside the component — the app
  must push today's total to the widget on every log.
- Interactive buttons need iOS/iPadOS 17+. This Mac's simulator is 16.2 →
  **test on the owner's iPad via TestFlight**.
- New app extension → first build needs the owner's interactive EAS login, or
  the local ASC key route (ship-ios-app skill, Phase 3 step 7d).

### B. Adaptive reminders (~2 days) — the v1.1 plan items that never shipped
1. Backoff: 2 reminders with no log in between → double the gap for the rest
   of the day, softer copy.
2. Snooze "Not now (1h)" action on the notification, beside "Log 250 ml".
3. Pace-aware spread: behind pace at midday → weight toward afternoon.
4. Evening cutoff learned from history (no logs after ~8pm → stop earlier).
All pure TS in `src/logic/reminders.ts` + one category change in
`src/notifications.ts`, with a test per rule.

### C. 13 languages (~2 days)
- One catalog file per language in `src/i18n/`, plus Color Catch's
  `src/i18n/device.ts` locale detection. TS rejects incomplete catalogs.
- `notice.*` (medical copy) and `notifications.messages` are rewritten per
  language, not translated.
- Declare the languages to iOS (`CFBundleLocalizations`) — see
  `docs/localization-plan.md` step 2.
- Store: per-country keyword research (app-store-scraper), not translated
  keywords. `store-assets/listing.json` via `release.mjs pull` first.
- Codex reviews every locale; captions via `compose-screenshots.mjs`.

### D. Ads (~1.5 days)
- `react-native-google-mobile-ads@17.0.0` — **pin it**: 17.1+ needs
  react-native ≥0.86, this app is on 0.85.3.
- AdMob account + iOS app + banner unit IDs (owner creates; test IDs in dev).
- Banners on **History and Settings only**. Never on Home, never full-screen,
  never in notifications (Guideline 4.5.4).
- Non-personalized ads only → no App Tracking Transparency prompt.
- SKAdNetwork IDs in `Info.plist` via the plugin config.

### E. Remove-ads purchase (~1 day)
- `expo-iap` (as Color Catch): one NON_CONSUMABLE, e.g.
  `com.teja788.waterreminder.removeads`, $2.99 US, regional points as Color
  Catch (IND ₹199, BRA R$12.90, MEX MX$39, …). Create it via the ASC API recipe.
- `src/pro.ts` becomes the entitlement check: purchase OR grandfathered.
- **Grandfather every existing user**: `getAppTransactionIOS()` →
  `originalAppVersion` (a BUILD number) < first 2.0 build → no ads.
- "Remove ads" + "Restore purchase" rows in Settings. `.web.ts` stub so iPad
  Safari testing keeps working.
- Paid Apps Agreement must be Active on this account (done for Color Catch).

### F. Retract the "no ads" promise — same version, no exceptions
- `docs/store-listing.md` lines 10, 15, 33 and keyword `no ads` (38) — and the
  live ASC fields they came from (promo text, description, keywords).
- `site/privacy.html` lines 29 and 39 → describe AdMob; push to `gh-pages`
